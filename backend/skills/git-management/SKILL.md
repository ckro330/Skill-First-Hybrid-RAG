# Git 管理 Skill（git-management）

## 目标

把工作区改动整理成清晰、可追溯的提交，并让用户对分支与历史状态始终可见。

## 使用场景

- 查看当前分支、工作区状态、未跟踪文件。
- 查看未暂存/已暂存差异、或与某个提交/分支对比。
- 查看提交历史，理解某次改动来源。
- 暂存并提交改动，撰写规范提交信息。
- 列出、新建、切换分支。

## 执行环境约定

- git 工具以 `backend/` 为工作目录执行，该目录位于仓库内，git 会自动向上找到仓库根。
- 路径统一用正斜杠 `/`；当前环境为 Windows。
- 仓库根目录文件用 `../` 前缀访问，例如 `../README.md`。

## 工作流程

### 1. 先看状态，再动手

1. 用 `git_status` 查看当前分支、已暂存/未暂存改动、未跟踪文件。
2. 用 `git_diff` 查看具体改动内容；改动多时先 `stat_only=true` 看统计。
3. 有疑问时用 `git_log` 看最近提交，理解当前改动的上下文。

### 2. 提交前核对

1. 确认要提交的文件范围，避免把临时文件、调试代码、密钥一起提交。
2. 用 `git_diff`（`staged=true`）确认暂存区内容与预期一致。
3. 提交信息要说明"做了什么、为什么"，简洁明确，不要写 "update"、"fix" 这类无信息量内容。

### 3. 暂存与提交

1. 用 `git_add` 暂存指定路径；需要全部暂存时才用 `paths=["."]`。
2. 用 `git_commit` 提交；可在 `paths` 中直接给出文件让其先暂存再提交。
3. 提交后检查返回的 `HEAD`，确认提交成功。
4. **绝不执行 push**；需要推送时提示用户手动执行。

### 4. 分支操作

1. 用 `git_branch(action="list")` 查看分支，确认当前所在分支。
2. 用 `create` / `create_and_switch` 新建分支；用 `switch` 切换。
3. `delete` 是破坏性操作：必须先向用户确认，且只用安全删除 `-d`。

### 5. 汇报

说明：当前分支、提交哈希与信息、涉及文件、未提交的剩余改动。

## 工具使用约定

- `git_status`：第一步，看全局状态。
- `git_diff`：看差异，支持 staged / ref / path / stat_only。
- `git_log`：看历史，支持数量、路径、引用过滤。
- `git_add`：暂存指定路径。
- `git_commit`：创建提交，不 push。
- `git_branch`：列出/新建/切换/安全删除分支。
- `read_file` / `grep`：查看提交前的文件内容与改动上下文。

## 安全与边界

- 不执行 `push`、`reset --hard`、`clean -fd`、强制推送等破坏性操作。
- 不擅自修改或删除用户分支；删除分支前必须确认。
- 不提交 `.env`、密钥、大体积二进制等敏感或不该入库的文件。
- 提交信息不得包含未经用户确认的敏感信息。
- 用户未明确要求时，不要自动提交；先展示状态与差异，等确认再提交。
